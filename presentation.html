Telegram-бот Kiuha

Как разрабатывался: порядок, трудности, ошибки, итог

Python 3.11XTTS v2 Ollama / Qwen3.5-4Bpython-telegram-bot

Проект собирался с нуля: от выбора стека до рабочего бота, который отвечает голосом друга.

Идея и цель

  • Бот @kiuhabot получает текстовое сообщение — но реагирует только тогда, когда в нём есть обращение по имени: «Киюха», «Кирюха», «Киюх» и варианты. Обычный текст в чате он пропускает и не отвечает.
  • Вместо заготовленных фраз используется нейросеть (LLM): она читает сообщение и сама придумывает живой, дружелюбный ответ по-русски — как отвечал бы настоящий друг.
  • Полученный текст озвучивается моделью XTTS v2 голосом друга. В качестве эталона используется запись friend.wav длиной 30 секунд — именно с неё модель «копирует» тембр и интонацию.
  • Готовый аудиофайл отправляется обратно в чат голосовым сообщением.

Дополнительные условия: из-за санкций облачный ElevenLabs недоступен, поэтому синтез делается локально. Хозяин проекта «полный ноль» в программировании — поэтому всё приходилось настраивать и писать за него, а в конце подготовить понятную инструкцию.

Порядок разработки

1. Выбор стека. Облачные сервисы озвучки отпали сразу — взяли локальный Coqui TTS (модель XTTS v2), а за «ум» ответа — локальную нейросеть Ollama.

2. Подготовка окружения. Системный Python 3.14 оказался несовместим, поэтому поставили отдельный Python 3.11 в D:\Python и установили все библиотеки (TTS, python-telegram-bot, httpx, torch).

3. Голос друга. Оригинальная запись friend_full.wav длилась больше 10 минут и весила 65 МБ — для XTTS достаточно короткого эталона, поэтому её обрезали до 30 секунд.

4. Сборка TTS. Библиотека содержит C++-расширения, которые пришлось компилировать: доустановили компилятор MSVC и Windows SDK.

5. Первый синтез. Проверили, что из текста получается корректный WAV-файл с нужным голосом (voice.wav).

6. Telegram. Вписали токен bots, подключили обработчик сообщений и организовали автозапуск через Планировщик задач Windows (задача KiuhaBot).

7. Мозги. Подключили Ollama через HTTP API, перебрали несколько моделей и остановились на лёгкой Qwen3.5-4B.

8. Финальные доработки. Фильтр обращения по имени, защита от эмодзи, увеличенные таймауты, исправление имени модели и инструкция Read_Me.txt для хозяина.

Трудности №1 — сеть и сборка

Санкции и соединения

  • ElevenLabs недоступен из-за санкций — заменили на локальную модель XTTS v2, которая вообще не требует интернета для синтеза.
  • Telegram напрямую не отвечал — подключили VPN Happ (туннель xray); только после этого бот смог подключаться к API.
  • Скачивание модели с облачного хранилища cloudflare постоянно обрывалось — перешли на зеркала modelscope.cn и hf.co, с которых модели скачались нормально.

Компиляция C++

  • Библиотека TTS собирает часть кода на C++ — без компилятора MSVC установка падала.
  • Даже с компилятором не хватало заголовочного файла io.h из Windows SDK.
  • Пришлось вручную скачать и переустановить Windows SDK версии 10.0.26100 — после этого нужный файл появился и сборка прошла успешно.

Трудности №2 — версии и выбор модели

Конфликты библиотек

  • Новая версия transformers 5.x сломала компонент BeamSearchScorer — пришлось понизить до 4.46.3.
  • torch 2.15 не мог загрузить веса модели — откатились на torch 2.5.1+cpu.
  • Системный Python 3.14 не поддерживал часть библиотек — использовали отдельный Python 3.11.4.

Подбор нейросети

  • Qwen2.5-7B оказалась тяжёлой: вместе с TTS компьютер с 8 ГБ видеопамяти RTX 3060 Ti «задыхался».
  • Qwen3.5-4B оказалась моделью с «размышлениями»: при маленьком лимите токенов весь бюджет уходил на мысли, а видимый ответ получался пустым.
  • Решение: взять ту же 4B-модель, но включить режим think:false — она стала отвечать сразу и заметно легче грузила систему.

Ошибки и как их исправляли

speaker_wav_pathНеверное имя параметра. В TTS 0.22.0 он называется speaker_wav — иначе модель жаловалась, что не задан голос.
Application.token=Неправильный способ передать токен. Верный вызов: Application.builder().token(...).build().
TimedOut (Telegram)Бот не мог связаться с API. Решение: включить VPN Happ и увеличить таймауты подключения и чтения до 90 секунд.
UnicodeEncodeError (эмодзи)Нейросеть вставила в ответ эмодзи, а модуль озвучки через кодировку cp1251 не смог его записать. Добавили фильтр, который убирает эмодзи перед синтезом.
Модель ARA не найденаВ коде осталось название модели от незавершённой вчерашней правки. Проверили папку моделей и заменили на реально установленную SOMPOA.

Итог

  • Бот успешно отвечает голосом друга — но только когда к нему обращаются по имени (Киюха, Кирюха, Киюх). Обычные сообщения он игнорирует.
  • Всё работает локально и без облачных сервисов: синтез голоса идёт на процессоре, а нейросеть Qwen3.5-4B — на видеокарте RTX 3060 Ti. Скорость и нагрузка устраивают.
  • Запуск автоматизирован: задача Планировщика KiuhaBot поднимает бота при входе в Windows, а при падении его можно запустить вручную.
  • Для хозяина подготовлен файл Read_Me.txt — понятная инструкция, что нужно включить (VPN, Ollama) и как запустить/остановить бота, чтобы не дёргать меня по мелочам.
  • Файлы проекта лежат в D:\Python\projects\: bot.py (код), run_bot.bat (запуск), friend.wav (голос друга), Read_Me.txt (инструкция).
  • Эту презентацию также подготовил я — по просьбе хозяина, чтобы зафиксировать весь путь разработки: порядок шагов, сложности, ошибки и то, как они были решены.
